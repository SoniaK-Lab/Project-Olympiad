# پل بالینی (Clinical Bridge)

سامانهٔ فارسی **تله‌منتورینگ پزشکی** که دانشجویان پزشکی را به منتورهای بالینی وصل می‌کند: برنامه‌ریزی جلسه، تماس تصویری، تکلیف و بازخورد، بیمار مجازی و فروم دانشجویی، همه در یک جا.

> این پروژه برای **آموزش** ساخته شده است. کیس‌ها و سناریوها فرضی‌اند و جایگزین نظارت بالینی یا توصیهٔ پزشکی نیستند. هرگز اطلاعات شناسایی بیمار واقعی را وارد نکنید.

## ایدهٔ پروژه

آموزش بالینی به دسترسی به استادان باتجربه وابسته است، و فاصلهٔ جغرافیایی یا اختلال در کارآموزی می‌تواند این دسترسی را قطع کند. «پل بالینی» تلاش می‌کند ارتباط منتور و دانشجو و تداوم یادگیری ساختاریافته را در یک محیط آنلاین ساده حفظ کند.

## امکانات

| بخش | توضیح |
| --- | --- |
| **ورود با ChatGPT** | احراز هویت از طریق میزبانی Sites؛ هیچ رمز عبوری در برنامه ذخیره نمی‌شود. |
| **نقش‌ها** | مدیر، منتور و دانشجو، با کنترل دسترسی کامل سمت سرور. |
| **جلسات** | منتور یا مدیر جلسه می‌سازد؛ دانشجوی مربوط حضور را تأیید می‌کند. تغییر برنامه، تأیید حضور را پاک می‌کند. |
| **تکلیف و بازخورد** | گردش‌کار `assigned → submitted → revision → submitted → approved` با پیش‌نویس، درخواست اصلاح و تاریخچهٔ کامل رویدادها. |
| **تماس زندهٔ دونفره** | تماس صوتی/تصویری WebRTC بین منتور و دانشجوی همان جلسه. صدا و تصویر هرگز روی سرور ضبط نمی‌شود. |
| **بیمار مجازی** | سناریوی تنفسی شاخه‌ای و قطعی (deterministic) برای دانشجو؛ هر اقدام زمان و هزینهٔ فرضی مصرف می‌کند و در پایان گزارش مرور اهداف نمایش داده می‌شود. |
| **فروم دانشجویی** | بحث همتا به همتا با دسته‌بندی، جست‌وجو، رأی «مفید» و امکانات نظارت (سنجاق، قفل، حذف نرم) برای مدیر. |
| **پیشرفت یادگیری** | ذخیرهٔ اهداف، بازاندیشی‌ها و وضعیت فعالیت‌ها برای هر کاربر، همراه با گزارش‌های تجمعی برای مدیر. |
| **نمای مدیر** | مدیر می‌تواند به‌عنوان یک منتور یا دانشجوی تعریف‌شده کار کند؛ هویت واقعی و مؤثر هر دو در رویدادها ثبت می‌شوند. |

## فناوری‌ها

- **چارچوب:** Next.js 16 و React 19 روی Vinext
- **اجرا:** Cloudflare Workers
- **پایگاه داده:** Cloudflare D1 (SQLite) با Drizzle ORM
- **رابط کاربری:** Tailwind CSS 4، shadcn/Radix، فونت فارسی Vazir (خودمیزبان)
- **ابزار:** TypeScript، Vite، pnpm، Wrangler

## ساختار پروژه

| مسیر | کاربرد |
| --- | --- |
| `app/api/bridge/[...path]/route.ts` | نقطهٔ ورود API |
| `app/` | صفحه‌ها، چیدمان، احراز هویت ChatGPT |
| `lib/` | منطق سمت سرور: جلسات، تکلیف‌ها، تماس، فروم، آمار یادگیری |
| `db/schema.ts` | طرح پایگاه داده (Drizzle) |
| `drizzle/` | فایل‌های مهاجرت SQL |
| `source-ui/` | رابط کاربری: صفحهٔ اصلی، فروم، بیمار مجازی و موتور آن |
| `worker/` | ورودی Cloudflare Worker |
| `scripts/` | اسکریپت‌های ساخت، نصب و اجرا |
| `tests/` | تست‌های بک‌اند و موتور بیمار مجازی |
| `BACKEND.md` | مستندات کامل بک‌اند و API |

## اجرای محلی

**پیش‌نیازها:** Node.js نسخهٔ `22.13` یا بالاتر و pnpm (نسخهٔ مشخص‌شده در `packageManager` فایل `package.json`).

<div dir="ltr">

```bash
pnpm install
pnpm run db:generate
pnpm run build

# مهاجرت‌ها را فقط یک بار روی هر پایگاه محلی، به ترتیب اجرا کنید
for f in drizzle/*.sql; do
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js \
    d1 execute DB --local --config dist/server/wrangler.json \
    --persist-to .wrangler/state --file "$f"
done

pnpm run dev
```

</div>

این نسخه به سرور نیاز دارد و با باز کردن مستقیم `index.html` کار نمی‌کند. اجرای پیش‌نمایش بدون هویت معتبر، صفحهٔ ورود را نشان می‌دهد.

## شروع کار مدیر

سایت در انتشار فعلی خصوصی است. **اولین ورود احراز هویت‌شده، مدیر اولیه را می‌سازد**، پس پیش از افزودن افراد به دسترسی میزبانی، خودتان وارد شوید.

۱. در «مدیریت کاربران»، منتور را با ایمیل واقعی حساب ChatGPT او تعریف کنید.
۲. دانشجو را تعریف و به منتور متصل کنید.
۳. هر فرد با اولین ورود ChatGPT به پروفایل مجاز خود متصل می‌شود.

این فرم فقط کاربر را مجاز می‌کند و ایمیل نمی‌فرستد. دسترسی به سایت در لایهٔ میزبانی (Sites) را هم باید جداگانه بدهید.

## API

همهٔ مسیرها زیر `/api/bridge` هستند. فهرست کامل و جزئیات هر مسیر در [BACKEND.md](BACKEND.md) آمده است.

| مسیر | کاربرد |
| --- | --- |
| `GET /me` | هویت و نقش فعلی |
| `GET/POST /members` | کاربران؛ ساخت فقط توسط مدیر |
| `GET/POST /sessions` | جلسات |
| `PATCH/DELETE /sessions/:id` | تغییر یا حذف جلسه (با `version`) |
| `POST /sessions/:id/attendance` | تأیید حضور |
| `GET/PUT /progress` | پیشرفت شخصی |
| `GET/POST /assignments` | تکلیف‌ها؛ همراه با `/:id/answer` و `/:id/review` |
| `/calls/:sessionId` | سیگنالینگ تماس WebRTC |
| `/forum` | فروم دانشجویی |
| `GET /admin-views` | فهرست حساب‌های قابل انتخاب برای نمای مدیر؛ فقط مدیر |

**قراردادهای مهم:**

- نوشتن هم‌زمان با نسخهٔ قدیمی با خطای `409` رد می‌شود (قفل خوشبینانه با فیلد `version`).
- درخواست‌های نوشتن باید `Origin` همان سایت و بدنهٔ JSON داشته باشند.
- همهٔ پاسخ‌ها `no-store` هستند.
- نقش هرگز از ورودی مرورگر یا `localStorage` پذیرفته نمی‌شود.

## انتشار

مهاجرت‌های تولید در فرایند انتشار Sites اجرا می‌شوند و manifest با `d1=DB` نگهداری می‌شود. پیش از تغییر راه‌اندازی از خصوصی به عمومی، جریان ایجاد مدیر اولیه را بازبینی کنید.

## محدودیت‌های فعلی

- اعلان ایمیلی و push وجود ندارد (فروم هم اعلان نمی‌فرستد).
- بازیابی حساب اختصاصی و پشتیبان‌گیری قابل مدیریت توسط کاربر هنوز اضافه نشده است.
- تماس تصویری از STUN عمومی گوگل استفاده می‌کند و **TURN پیکربندی نشده است**؛ در شبکه‌های محدود یا موبایل ممکن است وصل نشود. برای تولید، یک سرویس TURN احرازهویت‌شده لازم است. تماس بین شبکه‌های واقعی هنوز راستی‌آزمایی نشده است.
- فیزیولوژی، زمان‌بندی و هزینهٔ سناریوی بیمار مجازی **داستانی و آموزشی** است.
- ورود و خروج متعلق به ChatGPT است و برنامه خودش مدیریت نمی‌کند.
