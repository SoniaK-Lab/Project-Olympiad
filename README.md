# پل بالینی (Clinical Bridge)

**پل بالینی** نام برنامهٔ داخل مخزن Project-Olympiad است. این سامانهٔ فارسی به دانشجویان پزشکی و منتورهای بالینی کمک می‌کند جلسات را برنامه‌ریزی کنند، آنلاین گفت‌وگو کنند و تکلیف و بازخورد هر جلسه را پیگیری کنند. دانشجو می‌تواند با کیس‌های ساختگی، شبیه‌ساز بیمار و گفت‌وگوهای فروم تمرین کند.

سناریوها، زمان و هزینهٔ اقدامات شبیه‌سازی‌شده جنبهٔ آموزشی دارند. در یادداشت، تکلیف، فروم یا هر بخش دیگر اطلاعات قابل‌شناسایی بیماران واقعی را وارد نکنید.

## راهنمای نقش‌ها

| نقش | کارهای اصلی |
| --- | --- |
| **مدیر** | تعریف منتور و دانشجو، اتصال دانشجو به منتور، مدیریت جلسات، مشاهدهٔ گزارش یادگیری دانشجویان و نظارت بر فروم |
| **منتور** | برنامه‌ریزی و ویرایش جلسات دانشجویانِ متصل به حساب خود، تعریف و بررسی تکلیف، درخواست اصلاح یا تأیید پاسخ و مشاهدهٔ گزارش همان دانشجویان |
| **دانشجو (منتی)** | مشاهدهٔ برنامه و تأیید حضور در «جلسات من»، مشاهدهٔ تکلیف و بازخورد همان جلسه، تمرین با کیس‌های بالینی و بیمار مجازی و مشارکت در فروم |

- **جلسات من** عنوان، وضعیت زمانی و بازخورد هر جلسه را نمایش می‌دهد. دانشجو از همین صفحه به تکلیف و پاسخ آن دسترسی دارد. تغییر زمان یا هدف جلسه، تأیید حضور قبلی را پاک می‌کند.
- **تکلیف جلسه** با تعیین تکلیف شروع می‌شود. دانشجو می‌تواند پیش‌نویس خصوصی ذخیره کند یا پاسخ را بفرستد. پس از درخواست اصلاح، امکان ارسال دوباره باز می‌شود و پس از تأیید نهایی پاسخ بسته می‌شود. تاریخچهٔ ارسال و بازخورد حفظ می‌شود.
- **اتاق جلسه** چک‌لیست، یادداشت شخصی و تماس صوتی و تصویری دونفره دارد. منتور و دانشجوی همان جلسه هر کدام روی «پیوستن به تماس» می‌زنند. مرورگرها رسانه را با WebRTC منتقل می‌کنند و سرور برنامه آن را ضبط نمی‌کند.
- **بیمار مجازی** یک سناریوی تنفسی شاخه‌ای دارد. انتخاب معاینه، آزمایش یا درمان، مسیر سناریو و زمان و هزینهٔ فرضی را تغییر می‌دهد. در پایان، کاربر تصمیم‌ها و اهداف مرورشده را می‌بیند.
- **فروم دانشجویی** از موضوع، پاسخ، جست‌وجو و رأی «مفید» پشتیبانی می‌کند. مدیر می‌تواند موضوع‌ها را سنجاق یا قفل کند و محتوا را به‌صورت نرم حذف کند.
- **نمای مدیر** اجازه می‌دهد مدیر با نقش یک منتور یا دانشجوی تعریف‌شده کار کند. عملیات این نما روی دادهٔ همان حساب اعمال می‌شود. برای نمونه، در تاریخچهٔ تکلیف هویت مدیر و حساب انتخابی هر دو ثبت می‌شوند.

## اجرای محلی

نسخهٔ سروردار با Node.js `22.13.0` یا بالاتر مطابق `engines` و pnpm نسخهٔ `11.25.0` کار می‌کند. در ویندوز، برای بلوک Bash از Git Bash یا WSL استفاده کنید. نسخهٔ pnpm را با `pnpm --version` بررسی کنید. اگر فرمان `pnpm` در دسترس نیست و Corepack نصب است، از `corepack pnpm` به‌جای آن استفاده کنید.

۱. مخزن را بگیرید، وابستگی‌ها را از روی فایل قفل نصب کنید و Worker را بسازید.

<div dir="ltr">

```bash
git clone https://github.com/SoniaK-Lab/Project-Olympiad.git
cd Project-Olympiad
pnpm install --frozen-lockfile
pnpm run build
```

</div>

۲. مهاجرت‌های موجود در مخزن را به‌ترتیب روی یک پایگاه محلی تازه اجرا کنید. هر فایل فقط یک بار روی هر پایگاه اجرا می‌شود. ساخت مهاجرت با `pnpm run db:generate` برای زمانی است که طرح پایگاه داده را تغییر می‌دهید.

<div dir="ltr">

```bash
for migration in drizzle/*.sql; do
  node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js \
    d1 execute DB --local --config dist/server/wrangler.json \
    --persist-to .wrangler/state --file "$migration" || break
done
```

</div>

۳. اگر هر چهار مهاجرت موفق بودند، سرور توسعه را اجرا کنید و [نشانی محلی](http://127.0.0.1:5173) را در همان دستگاه باز کنید.

<div dir="ltr">

```bash
pnpm run dev
```

</div>

ورود و ثبت‌نام محلی و آنلاین در `/login` با کد ملی و رمز عبور انجام می‌شود. هر حساب جدید با نقش دانشجو ساخته می‌شود. حساب جدید خودکار مدیر نمی‌شود.

### رفع اشکال محلی

| نشانه | بررسی |
| --- | --- |
| `pnpm` شناخته نمی‌شود | در همان ترمینال `node --version` و `corepack pnpm --version` را بررسی کنید. |
| فایل `dist/server/wrangler.json` پیدا نمی‌شود | از ریشهٔ مخزن `pnpm run build` را اجرا و خروجی ساخت را بررسی کنید. |
| API خطای پایگاه داده می‌دهد | مطمئن شوید هر چهار مهاجرت موفق شده‌اند و مسیر ذخیرهٔ محلی `.wrangler/state` است. |
| ورود آزمایشی کار نمی‌کند | در کلون معمولی، آدرس 127.0.0.1 را روی همان دستگاه باز کنید. در پیش‌نمایش مدیریت‌شده، دسترسی و ورود Sites را بررسی کنید. |
| هنگام ذخیره خطای `409` می‌گیرید | آخرین داده را دوباره بارگیری کنید و تغییر را روی نسخهٔ تازه اعمال کنید. |

نسخهٔ قدیمی را می‌توانید با باز کردن [index.html](index.html) از فایل‌های کلون‌شده اجرا کنید. این نمونهٔ ایستا داده را در مرورگر ذخیره می‌کند. برنامهٔ فعلی از مسیر `/ui` روی سرور و پایگاه D1 استفاده می‌کند و داده‌های نسخهٔ قدیمی خودکار منتقل نمی‌شوند. [راهنمای نمونهٔ اولیه](CLINICAL_BRIDGE.md)



- ثبت‌نام در `/login` فقط کد ملی، رمز عبور و تکرار رمز می‌خواهد؛ حساب دانشجو بلافاصله فعال می‌شود. ایمیل، کد تأیید و تأیید مدیر لازم نیست.
- ورود فقط با کد ملی و رمز انجام می‌شود. ارقام فارسی و عربی پذیرفته و صفر ابتدای کد حفظ می‌شود. کد ملی با رقم کنترل بررسی می‌شود؛ این بررسی اثبات هویت فرد نیست.
- رمز بین ۸ تا ۱۲۸ نویسه است؛ PBKDF2-SHA256 با نمک تصادفی و ۱۰۰٬۰۰۰ تکرار ذخیره می‌شود. نشست تصادفی با هش سمت سرور و کوکی HttpOnly/Secure/SameSite به مدت ۷ روز معتبر است و خروج آن را باطل می‌کند. محدودیت تلاش روی حساب و IP در پایگاه داده اعمال می‌شود.
- مهاجرت `0004_national_auth.sql` باید قبل از استفاده اجرا شود؛ انتشار Sites آن را همراه خروجی اعمال می‌کند. حساب جدید هرگز مدیر نمی‌شود.
- برای انتقال حساب قبلی، کاربر در همان مرورگری که نشست معتبر میزبانی و هویت متصل به حساب قبلی را دارد یک بار کد ملی و رمز ثبت می‌کند؛ نقش و اطلاعات قبلی حفظ می‌شود. کد ملی به‌تنهایی به حساب‌های قبلی دسترسی نمی‌دهد. پس از انتقال، ورودهای بعدی فقط با کد ملی و رمز است.
- بازیابی خودکار رمز هنوز موجود نیست. کد ملی و رمز را در گزارش‌ها و اطلاعات بیمار وارد نکنید.


## معماری و مسیر فایل‌ها

برنامه از **Next.js 16 و React 19 روی Vinext** استفاده می‌کند. اجرای سرور با Cloudflare Workers است و داده در **Cloudflare D1** ذخیره می‌شود. طرح و مهاجرت‌های پایگاه با Drizzle مدیریت می‌شوند. رابط فارسی راست‌چین از فونت خودمیزبان Vazir استفاده می‌کند.

| مسیر | وظیفه |
| --- | --- |
| [`app/`](app/) | انتقال مسیر اصلی به `/ui`، سرو رابط و ورود با کد ملی و نشست سمت سرور |
| [`source-ui/`](source-ui/) | رابط فارسی، فروم، رابط و موتور بیمار مجازی |
| [`lib/`](lib/) | کنترل دسترسی و منطق جلسات، تکلیف، تماس، فروم و گزارش یادگیری |
| [`db/schema.ts`](db/schema.ts) و [`drizzle/`](drizzle/) | طرح داده و مهاجرت‌های SQL |
| [`worker/`](worker/) و [`vite.config.ts`](vite.config.ts) | ورودی Worker و پیکربندی ساخت، اجرای محلی و اتصال D1 |
| [`tests/`](tests/) | آزمون‌های API و موتور بیمار مجازی |

### API برنامه

مسیرهای جدول زیر نسبت به `/api/bridge` نوشته شده‌اند.

| مسیر | کاربرد |
| --- | --- |
| `GET /me` | هویت، نقش مؤثر و وضعیت نمای مدیر |
| `GET /members` و `POST /members` | فهرست کاربران قابل مشاهده و تعریف کاربر توسط مدیر |
| `GET /sessions` و `POST /sessions` | فهرست و ایجاد جلسات |
| `PATCH /sessions/:id` و `DELETE /sessions/:id` | تغییر یا حذف جلسه با نسخهٔ فعلی رکورد |
| `POST /sessions/:id/attendance` | تأیید حضور توسط دانشجوی همان جلسه |
| `GET /assignments` و `POST /assignments` | فهرست و ایجاد تکلیف |
| `GET /assignments/:id/history` | تاریخچهٔ قابل مشاهدهٔ تکلیف |
| `POST /assignments/:id/answer` و `POST /assignments/:id/review` | ذخیره یا ارسال پاسخ و ثبت بازخورد |
| `GET /progress` و `PUT /progress` | خواندن و ذخیرهٔ پیشرفت شخصی |
| `GET /learning-stats` | گزارش یادگیری در محدودهٔ دسترسی مدیر یا منتور |
| `/calls/:sessionId` | خواندن پیام‌ها و مسیرهای ورود، ارسال پیام و خروج WebRTC |
| `/forum` | موضوع‌ها، پاسخ‌ها، رأی و نظارت |
| `GET /admin-views` | حساب‌های قابل انتخاب در نمای مدیر |

API نقش و رابطهٔ منتور و دانشجو را سمت سرور بررسی می‌کند. درخواست‌های تغییردهنده باید `Origin` همان سایت و بدنهٔ JSON داشته باشند. عملیات نسخه‌دار در صورت تعارض `409` برمی‌گردانند و پاسخ‌های API با `Cache-Control: no-store` ارسال می‌شوند. [جزئیات بک‌اند](BACKEND.md)

## انتشار و محدودیت‌ها

- پیکربندی فعلی برای **Sites** است. فرایند انتشار Sites از manifest و مهاجرت‌های همراه خروجی ساخت برای اتصال D1 با نام `DB` استفاده می‌کند. انتشار مستقل به یک مسیر معتبر برای احراز هویت سمت میزبان و اتصال پایگاه نیاز دارد.
- تماس از STUN استفاده می‌کند. TURN در کد فعلی پیکربندی نشده و تماس میان دو شبکهٔ واقعی در مستندات پروژه تأیید نشده است. در بعضی شبکه‌های محدود، برقراری تماس ممکن است ناموفق باشد.
- ثبت کاربر و فروم ایمیل یا اعلان push ارسال نمی‌کنند. ورود و خروج با کد ملی و رمز عبور و نشست اختصاصی انجام می‌شود. بازیابی خودکار رمز هنوز وجود ندارد.
